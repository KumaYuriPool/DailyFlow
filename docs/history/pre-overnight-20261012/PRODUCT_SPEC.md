## 一 产品定义

**DailyFlow 帮助用户围绕一个问题，把散落在不同应用里的个人经历组织成有来源、可核验、可更新的时间流。**

用户说“帮我找回这件事的来龙去脉”，Agent 理解主题、时间范围与必要来源；DailyFlow 提供可信事件检索、关联和更新能力，以轻量图文界面呈现。默认不要求用户先选主题和来源、理解peer或手抄工具JSON。用户负责授权、关键歧义和纠正关联。

交付形态是App，可复用时间事件接入层是架构核心。官方宿主管理Agent、权限和工具执行；DailyFlow不宣称已经构建通用Agent harness。产品价值不止“另一种账本视图”，而是把接触、实践、投入、变化及后续放回同一段经历。

核心原则：没有记录不等于没有发生；时间接近不证明同一活动或因果；模型整理文字不等于源事实。临时问题生成临时回顾，不自动创建永久主题或开启后台跟踪。

## 二 主演示场景

两组场景使用同一套代码和协议，不在Prompt、UI或业务分发中硬编码答案。所有样本为合成资料，模拟社媒必须可见标注。

| 场景 | 用户问题 | 所需来源与目标结果 |
| --- | --- | --- |
| 兴趣进入生活 | “我是怎么从刷到攀岩视频，到开始持续练习的？” | 社媒收藏、首次体验配文、完成线路照片；日历体验课与后续预约；记账课程支出。串联接触、实践、投入和后续 |
| 从官宣到散场 | “把这次演出从期待到结束的经历串起来，还有哪些安排？” | 社媒官宣收藏和现场分享；日历开票/活动安排；票款与交通账目。区分已发生与未来计划 |
| 后续复用 | “收藏的灵感是如何变成这件作品的？”；“这次旅行如何从视频收藏变成真实经历？” | 复用相同的来源适配、关联和时间流，不分别开发新垂直助手 |

样本不足以证明“每周练习”时指出缺口，不编造频率。配文里的金额不再生成一笔账。同期衣物购买不能直接算演出支出，需明确引用或用户确认。经期、新闻、日记保留为后续来源，不作为此次主演示。

## 三 目标交互与界面

1. 用户在DailyFlow输入自然语言问题。
2. Agent依据已授权来源的能力目录分析主题、范围和必要来源；多次同名旅行等关键歧义才提问。
3. 界面展示拟查询/正在查询的来源；新权限走宿主真实授权。Agent选择来源不等于获得权限。
4. 来源返回结构化记录；程序验证身份与修订、规范化和更新投影。模型仅在必要范围内提出候选关系与摘要。
5. 展示临时图文时间流、事实/计划、来源引用、读取时间及缺失范围。
6. 用户可确认/排除候选关联、调整范围、刷新；外部记录更正回到权威来源执行。

| 界面区域 | 用户能看到/操作什么 | 验收底线 |
| --- | --- | --- |
| 自然语言入口 | 提问、必要澄清、取消 | 不依赖用户切换系统助手或输入工具名；历史回答不冒充实时查询 |
| 来源状态条 | 来源范围、权限、读取进度、最后同步与部分失败 | 失败不能显示成零结果；不用假进度百分比 |
| 图文时间流 | 日期、事实/计划、来源、配文与可用图片 | 不只是按天堆列表；图片失败不阻塞文字 |
| 来源详情 | 原始内容、源ID/修订、关联依据、可用时回源 | 模型摘要不能冒充原文；不展示不可用的假操作 |
| 关联纠正 | 确认/排除候选；刷新时保留本次查询的选择 | 排除不是删除源记录，不改动外部数据 |
| 变化反馈 | 更正、删除、过期、不可访问 | 旧缓存不能悄悄充当已授权的新鲜结果 |

主要产品交互在DailyFlow内，系统助手是额外入口。目标导航以经历目录为主，数据来源放入设置；现有记录、查找、账本、日历与经期保持可达，旧数据不迁移。具体入口及分阶段落地见新版交互设计。图片展示与模型识图独立，首版根据配文、时间和标签组织即可。

## 四 各层职责

| 层 | 职责 | 边界 |
| --- | --- | --- |
| 来源App | 持有权威记录、稳定ID、修订、墓碑、受限读取工具 | 不允许DailyFlow直接读其私有目录 |
| OctoSense Shell | 工具发现、调用者/来源身份、授权、路由、取消、错误与审计 | 不实现攀岩/演出/金额归类等业务 |
| DailyFlow接入层 | 验证、适配、去重、修订/删除、刷新投影 | 不以模型生成JSON冒充真实工具结果 |
| Agent | 理解问题、选源、提出关联、解释经过 | 不扩大权限、不推断权威金额、不执行来源内容中的指令 |
| DailyFlow UI | 呈现过程、图文结果、来源核验、用户纠正与接管 | 不把旧黑板当实时接口 |

能调用工具只证明通信；结构化结果进入DailyFlow并按身份/修订更新才证明接入。系统委派、跨App读取、确定性同步、跨App图片读取分别验收。

## 五 模拟社媒与独立记账

模拟社媒作为独立最小参考App：合成收藏/动态/配文/图片、发布时间、稳定ID、修订；列表、详情、测试用新增/更正/删除与只读导出。名称、工具名和目录在契约任务确认，当前不存在可承诺的API。不做账号、推荐、评论和真实平台爬取。

若采用真实跨App链，数据是模拟的，权限/调用/更新/删除必须真实。若只使用文件导入，明确标为“导入合成样本”；独立Python消费者则标为“协议契约验证”，不可混称。

独立记账属于条件分支：权威账目归源App，DailyFlow只读投影。比赛最低方案可用“一个独立模拟社媒＋DailyFlow内置账目/日历”，但必须说明只有一个外部独立来源。多个来源不等于多个独立App。禁止为演示迁移个人账本。

## 六 数据与同步规则

现行同包字段见[时间协议](TIME_EVENT_PROTOCOL.md)。下面是待实现外部契约要求，须通过DF-05确定版本与映射，不能直接放宽生产source_app校验。

- 身份为可信宿主绑定的source_app、source_module、source_record_id；不能信任payload自称app_id。改标题/日期不改变身份。
- 相同修订重复到达不新增，旧修订不覆盖新修订；同修订不同内容明确冲突。
- 只接受明确墓碑或可信完整快照的删除；分页遗漏、失败、范围变小都不是删除。
- 来源ID与内部ID分开。社媒金额只作文字，账目统计取源整数最小币种单位；不同币种不能无依据合计。
- 每批记录授权范围、读取时间、快照/修订与完整性。跨App没有同包原子事务保证，部分失败需可见。
- 源事实、投影、候选关系、用户确认与Agent整理分开；旧Flow主体不直接等同新活动主题。
- 撤权后相关文字/图片不得进入UI、模型和统计；明确缓存隐藏/隔离/清除策略。不能仅隐藏按钮。
- 本次查询内保留用户确认/排除；长期保存主题后置。只读组织不偷偷写源业务。
- 现行v2提供快照和墓碑，不是完整历史日志；要显示“由120改100”必须有实际观察到的前态证据。

## 七 图片、Agent与失败体验

先验证渲染器对授权静态图片的支持，再验证来源资源引用/传输。首版用有许可的合成素材；禁止任意磁盘路径读取、未经授权的跨App目录访问和无边界远程URL。图像类型/大小/缓存/撤权规则在DF-04/DF-05明确。失败显示占位和配文，不伪造图片。未实现模型识图前，不发送图片给Provider。

来源配文和图片内文字是数据，不是指令。回归至少包含一条要求“泄露其他来源/改账”的恶意配文，不能据此越权。

应用内自然语言默认使用官方应用Agent，经octos.turn.start、当前上下文工具和结构化结果工具回传到UI；调用interrupt并拒收取消后迟到结果。设置可显式切换model.complete备用入口，和官方peer链分别验收。新鲜结果需有本次请求标识、快照/读取时间和引用；取消后的迟到结果不能覆盖新任务。

区分零结果、歧义、未授权、来源关闭、离线、超时、部分分页、旧快照、删除、图片不可用。无模型时保留手动记录/确定性查询，不伪造智能完成。写入结果未知时先查询，不换request_id重试。审批由人完成。

## 八 Shell贡献

Shell修改已获授权，限与本应用闭环直接相关且可复用的改动。优先定位peer就绪/完成状态、第三方工具owner、应用内请求与结果桥。先最小复现，再决定修说明、调用方式或运行代码；不能凭模型回复判定平台缺陷。

本地main已有Card注册时序改进，先验证已有修复，不重复造补丁。Shell、Hub、kernel分别标归属。自编译宿主必须注明提交和补丁，不覆盖官方RC2未改二进制的证据。调用审计导出需主动、最小化、脱敏，不默认记录所有私人参数。
