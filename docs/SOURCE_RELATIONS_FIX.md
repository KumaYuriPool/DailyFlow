# 无命名 Flow 的源关联修复 · 0.6.2

2026-10-06。用户报告保存后的日历快捷入口多余，以及“做SPA ¥350”和“已发生·做SPA”在普通日历分列。只读核查确认费用只计一次；旧实现创建费用和事项后，relation_add 因 flow_id 为空跳过关联。

## 当前行为

- expense_for / follow_up / fulfills 可以以空 flow_id 关联明确源 ID，不强制创建命名 Flow。belongs_to 仍必须有有效容器。
- 非空 flow_id 的关系继续校验来源属于该范围；按范围查看全局关系时，两端都必须属于所选范围，防止过滤后把费用隐藏到范围外事项下面。
- 普通日历同日已发生事项及其明确费用显示一项，并显示费用合计；账本仍只算独立费用源。跨日付款保留在实际付款日，不改日期或金额。计划与撤回状态不伪装成已发生事项。
- 事项详情可打开各笔关联费用，费用详情可返回相关事项。修改金额后日历重算；删事项保留费用并恢复单独展示，删费用保留事项。
- 保存后的对话动作移除“在日历查看”，保留源记录；详情继续提供“定位到日历”。

## 旧记录修复

新增 `src/39_relation_repair.splash`，当前14个编译模块。启动读取完成后，在候选副本中检查旧复合收据。只有同时符合以下证据才补 expense_for：原始新增expense请求明确带event_title，未指定主体/Flow/后续/既有事项；收据record_id精确对应费用；原分配器的紧邻evt编号；两条修订均为1、未归组；原始名称/日期/金额/时间吻合；创建时间顺序一致且相差不足1秒；两端没有任何已有关系。不是同名/同日去重，也不按近似内容猜关系。

提交前写入并核对 `pre-source-relations-v1-<旧revision>.json` 完整备份，保留双槽事务。只有关联、数据库revision和source_relations_version标记变化；源ID/金额/日期/修订、历史收据与Flow不改。备份不完整或写入失败时不切换内存状态，旧记录保持。成功后重启不重复迁移。已更正、凭据缺失、冲突或不能证明的记录不自动修复。此为启动升级维护，不是搜索/查询写数据。

本轮没有直接写个人状态文件或关闭用户窗口。只读核查的旧SPA记录符合恢复条件；正常退出并重开已有AI启动器后执行上述备份/恢复。原生层、Provider和启动器未改，未提交/推送/发布。
