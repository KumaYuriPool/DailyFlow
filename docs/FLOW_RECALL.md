# 按需查找与时间线 · 0.6.1

2026-10-06，用户授权继续精简 Flow 常驻列表，并要求原型。本轮移除常驻第二栏，保留 App 导航、对话和按需工作区。历史 Flow、主体及关联不删，搜索不创建新 Flow。没有改 Shell/Rust 或个人数据，没有提交或发布。

## 实际交互

- 左侧“查找”输入名字或记录名称，搜索/回车；空查询不列出历史，每页20条。
- 时间线显示日期、记录和来源；计划明确标识，日精度不编造时刻，经期区间显示一次。
- 点击看源记录，修改后返回会重新查找；同源更正/删除实时反映。
- “为什么找到这些”按需展开依据；详情的“调整关联”默认折叠，旧关系管理页从这里进入。
- 顶部“范围”先搜索再选，最多10个名称结果，不默认铺开历史。选择范围改变聊天语境，查找记录不会。
- 日历条目直接打开源记录，源详情可回看主体时间线。返回对话保留草稿。

## 接口与匹配边界

`src/32_recall.splash` 消费注册来源 `source_snapshot` 和已保存关系，不互读模块私有数组。只读工具 `dailyflow.recall`：`text`（最多80字）、`flow_id`、`limit`（默认20、最多50）、`offset`、后续页必带 `snapshot_revision`。

1. 标题字面子串匹配；唯一完整匹配已有主体名称时看该主体全部成员。部分匹配列出候选范围、条数及起始日，不擅自合并同名主体。
2. 仅沿 `expense_for/follow_up/fulfills` 明确关系扩展，使用邻接表和已访问集合，避免环和重复输出。`belongs_to` 不当作具体活动关联。
3. 搜“团子洗护”不会因同主体/同日带入猫粮；搜“团子”可查看整个主体。
4. 按开始日期、已知分钟排序；同日未知时刻保持来源顺序，不表示因果。当前单包源ID全局唯一，公开事件另带模块/App命名空间。
5. 返回源身份、修订、区间、依据、总数和分页，不改业务数据或收据。数据变化拒绝旧分页，UI 自动回第一页。

**不是任意自然语言语义检索。** 应用内模型能力目录尚未接入 recall，本轮入口是查找工作区和声明工具。长问句、同义词、没存过的信息不保证匹配，不靠模型猜关联。本轮无新增真实 Provider 请求。

**不是无限容量或跨 App IPC。** 当前单包13模块，仍沿用原容量和事务边界。匹配集合在内存排序，分页限制展示/返回体，不宣称大规模索引性能。既有主体组织与80个Flow容量未改；本轮消除常驻列表，搜索不再生成新的持久入口。

## 原型与验收

线程 visualization 目录 `dailyflow-recall.html` 提供“边聊边找”（对话＋右侧回顾）和“专心回看”（集中回顾）。全部为固定示例，不读取实际数据或调用 Agent；原型中的聊天查找是交互方向，不是已上线的模型能力。

证据 `build/flow-recall-r1/`：

- `contracts-final2`：21次真实 Splash 调用，明确关联扩展、不误混同主体/同日记录、去重/时间排序、第三来源区间、候选范围、分页、更正/删除、重启、只读与不新建Flow。
- `ui-wide-final2/ui-narrow-final2`：实际点击查找、详情、更正后返回、空态、草稿/范围保持、重启，最终源码；截图已查看。
- `agent`：原43项注入断言及短延时的实际超时；`business`：原15次事务/幂等调用；`chat-regression`：原回复去重、折叠、来源、布局/上下文实际点击（注入模型）。
- 原型 `check-recall.cjs`：两布局、搜索/空态、来源/依据、排序、经期、返回、320/360/768/1024宽度通过，截图已查看。早期系统Node过旧和沙箱阻止Edge，随后用已有Node及获准的隔离浏览器。原型沙箱不允许form提交，改点击/回车后通过。

最终包检查及保护/清理核对在 final-gate.log / final-audit.json。正常退出再开已有AI启动器加载；没有关闭用户窗口。
