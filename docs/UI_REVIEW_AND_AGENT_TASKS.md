## 本轮优化目标与共同契约

以下是下一轮实现的目标，不是已经完成的界面。

- 保持“日历为主入口”。顶部品牌缩为紧凑标识，日历/Flow/记录/对话作为主要目的地；提醒和设置保留清楚入口。先通过 412 宽度实测再决定具体导航排布，不能只凭静态图取消已有功能。
- 基础间距采用 4/8/12/16/24；页面边距 16；标题约 20–24，正文约 14–16，辅助文字约 12–13 逻辑单位。先以实际字体与缩放检查可读性，不把建议值当作已验证的 Splash 渲染尺寸。
- 主色沿用蓝绿色，背景近白，正文深色。选中状态除了颜色，还配合标签/字重/轮廓；删除使用独立区域和明确文案，保留现有确认语义。
- 日历首屏目标：紧凑导航、月份切换、完整当月与至少一条当天摘要可以同时看到；没有事件时显示相关空状态与添加入口。干净日历默认不擅自显示经期标记。
- 时间线行应有日期、类型、标题、核心值/状态与进入详情提示。金额对齐、长标题可换行或明确截断，不能把内容挤成居中按钮文字。
- 所有页面展示当前筛选，能清除；从日历/Flow/提醒进入详情后，返回恢复来源日期、组和筛选。切换页面存在未保存草稿时，至少保留草稿或明确确认丢弃。
- 提示类型分为成功、校验错误、宿主不可用、存储保护。不得隐藏保存失败、丢失输入，或用视觉成功替代真实写入结果。

## 多 Agent 分工与执行顺序

建议 **1 个主 Agent + 3 个工作 Agent**。主 Agent 先完成 T0，然后 T1/T2/T3 可并行。T4 由主 Agent 集中合入与回归；需要独立复核时，可复用已完成工作的 Agent 做只读评审。当前任务包没有自动创建或启动这些 Agent。

| 任务 | 责任人 | 写入边界 | 交付 | 依赖 |
| --- | --- | --- | --- | --- |
| T0 样式与页面契约 | 主 Agent | 正式 main.splash 的公共样式、导航、顶栏、反馈与返回状态约定 | 可运行基础版、共享字段/控件 ID/样式说明、冻结的共同基线 | 无 |
| T1 日历与 Flow | Agent A | 隔离副本的 calendar/flows 分支及其专属 UI 辅助函数 | 优化月历、Flow 列表/详情、日期与筛选反馈、真实截图及补丁 | T0 |
| T2 记录与详情 | Agent B | 隔离副本的 records/edit 分支及专属 UI 辅助函数 | 记录行、详情查看/编辑、字段标签、保存取消与删除、真实截图及补丁 | T0 |
| T3 对话、提醒与设置 | Agent C | 隔离副本的 chat/alerts/settings 分支及专属 UI 辅助函数 | 状态卡片、模型不可用体验、提醒卡片、设置分组、真实截图及补丁 | T0 |
| T4 合入与验收 | 主 Agent | 正式 bundle、测试适配、最终说明和证据 | 三组改动合入、业务/路由/视觉回归、更新验收报告与 agent.md | T1/T2/T3 |

### 为什么采用隔离副本

所有页面目前都在一个 `main.splash` 中。多个 Agent 同时直接改正式文件会覆盖公共逻辑；仅按“页面名字”口头分工不足以避免冲突。仓库也有大量未提交修改，不能从旧 Git HEAD 建一个缺少当前成果的工作副本。

T0 完成后，主 Agent 将**当前完整 bundle**复制到 `build/ui-r1/{calendar,records,states}/bundle/`，保存基线哈希。工作 Agent 只编辑自己的副本，保留同一 app ID 也必须使用不同 `--app-data` 和空闲端口。可预留 8173/8174/8175，启动前检查占用，发现占用就选新端口，不能关闭占用者。

每个工作 Agent 返回：相对共同基线的补丁、涉及的函数和 UI 分支清单、控件 ID 变化、调用的现有业务函数、截图/快照/数据比对、未解决问题。主 Agent 按 T1 → T2 → T3 应用已审阅的局部差异，**不得用某个副本整文件覆盖正式入口**。重叠的共享样式和函数统一由主 Agent 处理。

这是开发隔离机制，生产依然为一个 Splash 入口。不能为拆任务引入未经支持的 import、生产代码生成器、Rust 或后台辅助服务。

## 可直接分配的任务提示词

### T0 — 主 Agent：先统一基础

读取工作区 agent.md、项目 AGENTS.md、本文件、DATA_PROTOCOL.md 和 MVP_ACCEPTANCE_REPORT.md。以当前未提交的正式 bundle 为基线备份。只使用 OctoScript/Splash 优化公共布局与样式：紧凑品牌/主导航、持久选中态、主次与危险动作、局部反馈、详情来源/返回契约。验证可用的 Splash 属性和样式复用方式，不发明 API。不要修改数据 schema、金额计算、去重、存储保护与规则逻辑。必要路由状态只做内存 UI 状态。提供公共变量、辅助函数、保留控件 ID 的清单，创建三份当前基线副本后再分发 T1/T2/T3。使用隔离数据实际启动、截图、查看控件尺寸，保护现有用户数据与运行时修改。

### T1 — Agent A：日历与 Flow

先读共同约束与 T0 契约，只修改分配给你的 bundle 副本。压缩日历顶部，将日期跳转变为按需出现；清楚区分今天、选中日、普通日、月外空位。保留真实公历算法和干净默认视角。Flow 分成列表与详情，时间线优先展示，管理动作按需展开；明确过滤与清除入口。与 T2 共用的记录行只能按 T0 已约定结构实现，不能自行重写共享 helper。公共状态变更向主 Agent 提建议。验收大小月、2000/2024/2100 二月、跨年、今天/选择/跳转、Flow 隐藏/删除后源记录保留、日历进入详情及返回；报告 412×892 首屏与长名称场景的实际截图与控件树。不得改存储、规则或生产主文件。

### T2 — Agent B：记录与详情

先读共同约束与 T0 契约，只修改分配副本中的 records/edit 和专属 UI helper。记录用可点击内容行展示，金额与任务状态突出，提供明确模块过滤。详情查看与编辑区分，有永久字段标签、保存与取消、明确来源返回；草稿不能被导航静默丢弃。Flow 关联是次级管理区域，删除保留确认并与保存分离。沿用现有 save_record/task_action/toggle_member/delete_record 等业务入口；不改变金额、经期、去重、任务状态语义。验收新增/改/删、无效金额/日期、重复经期、失败保留输入、跨组单次计费、完成/延期、长标题、返回恢复来源上下文。提交局部补丁、ID 映射、真实截图和文件状态对照。

### T3 — Agent C：对话、提醒与设置

先读共同约束与 T0 契约，只修改分配副本中的 chat/alerts/settings 和专属 UI helper。对话采用输入、反馈与手工操作卡片，模型不可用时以中文说明下一步，原始错误可查看，保留输入；不能暗示模型可用或生成假成功。提醒卡片突出事项、到期、状态与动作，背景能力说明降为帮助信息；不新增关闭后唤醒承诺。设置按隐私、预算与提醒、数据管理分组；导出恢复显示清楚的结果和影响，保留恢复保护。不得修改模型调用协议、规则检查、持久化与 backup 格式。实测错误态、存储保护、隐私开关、预算首次越限去重、任务进入详情、备份恢复，以及窄屏长错误文字。提交局部补丁、ID 映射、截图与验证结果。

### T4 — 主 Agent：合入与独立复核

逐项检查工作 Agent 的差异，只合入各自归属范围，公共冲突人工整合。适配现有桥测试时使用稳定控件 ID，不为了通过测试删弱数据断言。保留原 MVP 证据，新增 `build/ui-r1/integration/`。验证所有页面、空状态、长文案、失败状态、返回路径、重复点击、未保存草稿、窄窗口与较宽桌面窗口。若宿主桥支持尺寸调整，先查已有 API，再测 412×892 和较宽尺寸；不支持时明确未验证，不伪造截图。复测预算/任务/Flow/存储关键业务，最终 stamp/check、截图实际查看，关闭本轮进程。更新 UI 验收、README/操作说明与 agent.md；不提交、推送、发布。

## 统一验收清单

- 任何时刻可以识别当前主入口、所选日期或 Flow，详情可返回来源；没有“过滤存在但不显示”的页面。
- 主要保存/新建动作明显，危险动作不混入普通内容行；点击目标通过真实 `/snap` 测量。
- 412×892 中不发生横向溢出、文字重叠或重要动作不可达；完整月历与至少一条当天摘要同屏。
- 每个模块至少提供空、常规、长文本、失败四类状态证据；日期/金额/来源长文本不影响其他内容。
- 成功仅在实际保存后出现；保存失败、模型不可用、数据保护有清楚文案且保留可恢复路径。
- 原数据与运行时保护不变；业务回归仍通过。视觉验收与 gate 分开报告。
- 较宽桌面布局与 7 天连续试用单列结果，没实际测过就标“未验证”。

建议实施优先级：先 T0，再并行 T1/T2/T3，最后 T4。首轮不要同时加入新业务功能、真实模型集成或更换整体色彩风格，以便判断 UI 改善是否影响已有业务。
