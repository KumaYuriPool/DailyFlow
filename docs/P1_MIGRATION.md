# P1 收敛与迁移冻结

2026-10-04。用户已授权按 P0–P4 实施；不修改平台、不提交发布。

旧代码及个人应用状态已备份到 `build/event-flow-r2/baseline/`，测试一律用新隔离目录。

- schema_version 保持 1，新增 event_flow_version=2。源支出保留原 ID、修订、金额和有效 Flow 引用；旧 receipts 原样保留。旧收据请求仍可核对，不迁移清空。
- 非支出历史记录及仅包含这些记录的 Flow 留在容器中，不进入公开快照、查询、UI 或模型。旧 task 不自动转成新事件，因为旧通用任务不构成明确事件关联证据。
- 首次实际写入前保存原始状态到 pre-event-flow-v1.json；备份失败禁止写入。启动本身不改个人状态。新增独立 calendar_events、relations、tombstones；不凭旧账目生成虚构护理事实。
- 记账公开源快照和写入适配器，日历只消费版本化信封；Flow 持有节点 ID 和关系，不复制费用。单候选状态一次双槽提交，成功后重建投影；协议可独立用夹具验证。
- P0 中“最近金额唯一”不足以确定更正对象：更正必须通过明确的标题/主体/日期/原金额筛选得唯一候选，否则追问。关系只来自明确用户内容或明确上下文，不以相邻日期创建关系。
- 保持 request_id 为兼容收据键；change_id 按模块、源 ID、源修订生成，不能与复合请求收据混作同一粒度。
- 源码按存储、记账、日历投影、Flow、协调、Agent、界面分文件；构建为单 Splash。模块边界静态检查与运行夹具均必须通过。
- 移除旧多应用目录的运行/构建地位，保存到 archive；新产品仅日历/账本主入口、统一输入、事件工作区与次级数据管理。

P2/P3 的通过依据须记录到新的验收报告；0.3.0 证据仅作基线。
