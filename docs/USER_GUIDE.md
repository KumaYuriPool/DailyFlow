# DailyFlow 0.3.0 Windows 试用说明

## 启动与数据位置

需要自动记录时，双击项目根目录 `run-dailyflow-ai.cmd`。它启动完整 OctoSense 桌面，使用本机已有的 AI Provider 配置；该入口的数据保存在 `.local-state/desktop/`。本轮真实模型验证通过，不需要把密钥写进 DailyFlow 包。

`run-dailyflow.cmd` 或 `run-dailyflow.ps1` 仍启动独立 card-host，使用 `.local-state/dailyflow/`。这个手工入口没有 model 服务；对话失败不代表完整桌面的 Provider 不可用。旧手工数据与桌面数据独立，启动不会自动复制或迁移。不要对同一数据目录同时开启多个实例。

测试证据使用 `build/agent-flow-r1/` 隔离数据，不是你的个人记录。新入口需要工作区已有的 release `octosense.exe`、`hub.exe` 与包含 `cryptography` 的 Python 3.10+。脚本自动尝试已有 Codex Python 运行时，不安装依赖；也可用 `run-dailyflow-ai.ps1 -PythonPath <路径>` 指定现有环境。Provider 默认读取用户目录的 `.octosense/octos-home/.octos`，其他位置可用 `-CoreDir` 指定。

启动器窗口会等待桌面退出，正常使用时关闭桌面即可。它只为本地开发制作临时签名目录，不是商店安装或发布；普通启动不开放 UI 测试远程端口，同目录重复启动会被拒绝。实际账目、双槽文件与备份位于 `.local-state/desktop/apps/dailyflow/`，`home/` 保存该隔离桌面的状态。启动失败可查看 `.local-state/desktop/desktop-launch.log`。

## 用一句话记录

1. 打开“对话”，例如输入“今天买猫粮花了 45 元，归到宠物照护”。内容明确且业务校验通过后自动保存，不需要再手工建立 Flow。
2. 金额、日期、归属或任务时间不明确时会先追问；补充信息后继续同一事项。追问时不会先保存半条记录。
3. 保存反馈来自实际业务写入结果；随后到 Flow 查看记录节点。模型不可用或业务保存失败时保留输入。
4. 同一条已处理输入重复发送不会重复写入。保存结果不明时先查看记录，不要把原事项当新输入反复提交；“重试原保存”保留原请求标识，用于核对同一次保存。
5. 可取消当前事项或修改输入；过时模型回调不会继续保存。**对话草稿和追问上下文只保留在当前运行会话，关闭后不恢复**，已保存记录与幂等收据会持久化。

本轮实际验证了猫粮 45 元、猫砂含糊追问后补充 26 元、自动复用“宠物照护”并合计 71 元。并未穷尽模型对所有口语的理解；记录类型、实际日期、金额和来源仍由业务层校验。未来计划应创建任务，不能记作实际消费；新闻须有用户提供的真实出处。

## Flow 与手工操作

- **Flow**：默认先看概览，选择一个 Flow 后显示按日期排列的相连节点。点击节点打开源记录详情，返回可回到原 Flow。连线只表示归属和时间顺序，不表示因果关系或自动执行动作。管理操作折叠保留，可改名、隐藏或删除；删除 Flow 不删除源记录。
- **日历**：切换月份、选择日期或用 `YYYY-MM-DD` 跳转。记录与 Flow 引用同一源数据，跨 Flow 不重复计费。
- **记录**：仍可手工创建、编辑和删除记账、经期、任务及新闻。现有记录的纠正以详情编辑为主；保存失败保留输入。
- **标签**：业务类型由记账、任务等模块定义；自定义标签只保存用户明确提出的内容。没有全局固定标签词表。当前未提供完整独立标签管理页。
- **经期**：设置中主动启用后才能写入；默认隐藏敏感记录。宽泛工具查询和模型上下文不返回隐藏经期记录；磁盘数据和备份仍包含原始内容。
- **任务与提醒**：填写日期及 `HH:MM`，按北京时间处理；详情可完成、延期、取消或重新待办。运行中检查到期任务，重开时补偿；关闭应用后不会主动唤醒。
- **预算**：月预算 0 为关闭，首次越限产生提醒；跨组不会重复合计，已读提醒不会反复出现。

## 备份、恢复与容量

设置中的导出会把 `backup.json` 写入**当前入口的数据目录**，不要把旧手工目录与桌面目录混淆。恢复前先放入对应备份，界面要求二次确认并保存 `before-restore.json`。恢复会替换记录、Flow、提醒和幂等收据；**恢复旧备份后，不要重新投递备份之后结果未知的旧自动请求**，因为其收据可能已回退。

自动保存最多保留 **128 条请求收据**。达到上限后，新自动写入会明确失败，旧请求仍可核对，手工新建与更正可继续。不要手工删收据来绕过限制。记录上限 800、Flow 上限 80 是格式约束，不是极限容量性能承诺。

旧 `expenses.json` 仍需设置中显式导入，按旧 ID 去重，原文件不改。日期支持 1970–2100，记账为人民币、最多两位小数；不支持多币种、多设备同步或多实例并发写入。
