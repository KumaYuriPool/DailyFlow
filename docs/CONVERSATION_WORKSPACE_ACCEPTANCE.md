# 四列对话工作区 0.5.2 本地验收

日期：2026-10-06（Asia/Shanghai）。用户要求“继续接入”，本轮仅改 DailyFlow 应用源码、生成包、测试和交接文档。没有修改／重编译 Shell、App Hub、Makepad 或启动器，没有提交、推送或发布。以下结论优先于后面的历史 0.5.1 记录。

## 已接入实际 DailyFlow

- 宽屏为 App 栏、Flow 栏、对话、工作区四列；工作区按需打开。放大隐藏对话并扩展工作区，“恢复”回到原列宽；“收起”保留当前路由，再点“打开工作区”继续原页面。
- 对话与工作区是保留在树中的独立列，切换布局不重建整棵树。聊天草稿、未保存的编辑字段、搜索文字、年月／日期／视图／Flow 范围保留；布局和浏览操作不写业务数据。仍不承诺草稿或会话跨程序重启。
- 完整 Shell 使用既有 `on_app_resize` 回调，以**应用内容区 960 逻辑像素**为分界。窄于分界隐藏 Flow 栏，对话与工作区分层查看；拉宽后回到并排。保留“并排查看／单列查看”手动选择，下次窗口尺寸变化重新按可用宽度计算。
- 独立 card-host 没有该回调，默认单列；窗口较宽时点“并排查看”。此宿主不声称能自动随窗口宽度切换；没有为此修改原生层。
- 宽屏点“以这一天补记”更新输入语境并显示对话，工作区继续保留；窄屏返回对话。浏览本身不改变补记日期。发送消息也不会自动收掉宽屏工作区。
- Flow 栏现在在加载后及数据变化时动态刷新，显示真实名称、支出与未完成计划数；移除原来的固定示例描述。保存源账目的更正后，侧栏汇总同步更新。日历留出滚动条空间，短窗口通过纵向滚动查看后续日期和详情。

# 对话工作区 0.5.1 本地验收

日期：2026-10-05（Asia/Shanghai）。仅应用层 Splash / 构建与测试脚本 / 文档改动；未修改或重编译 Shell、Hub、Makepad、启动器，未提交或发布。

## 实际交付

- 对话首页与常驻输入，左侧对话／日历／账本／全部入口；顶部 Flow 搜索选择与“说件新事”。真实状态为空时不生成示例聊天、已保存回执或虚假记录。
- 应用入口、日历视图与 Flow 分别选择；固定搜索框配独立结果列表，支持来源“日历／记账”搜索、无结果提示、关闭返回。
- 普通／账本日历保留年月、浏览日期、范围、草稿与输入语境。日期数字居中，选中为实心圆，今天细圆环，邻月日期灰显。金额显示在日期下方；日格不再用整格底色或 `·N` 前缀。
- 浏览日期仅改变查询。“以这一天补记”明确改变输入日期并回到对话；会取消旧模型请求，迟到响应不能写入。模型请求使用独立的 `displayed_date` 和 `actual_today`。
- Flow 展示真实汇总、事实／费用归属／明确后续计划；节点先查看后修改，金额更正保留原 ID。回执可跳源记录、日历或事件关系。
- 新对话清空输入、旧回执及事件语境，恢复今天。普通页面导航保留草稿；草稿、会话及补记日期不跨重启。

## 经用户允许采用的替代方案

本版采用**左入口栏 + 顶部 Flow 选择 + 整页工作区**，宽窄屏均使用此结构。搜索从下拉按钮打开整页选择器。没有实现预览的独立 Flow 左栏、对话与右工作区四列并排、并排面板放大／收回，也没有农历。没有新增可安装 App 或空功能入口。

这些是本次实现边界，不能把分层页面说成预览布局已经完整复刻。用户允许绕不过时换方案或暂不做；本轮未为这些项目修改任何原生层。

## 本次纠正的历史结论

接手时 `src/60_ui.splash` 仍为日历入口，`00_storage.splash` 却引用不存在的 `home_chat`、`flow_list`，且 boot 中有多余括号和示例会话注入。因此旧交接文字不能作为当前源码的运行证据。

本次完整月历与多页面能在现有二进制正常运行；未证实旧文档“必须修 runtime 的 widget 编译预算”是唯一原因。真实遇到的问题包括不支持的字符串方法、父子视图异步同时重建导致结果丢失、日格金额裁切。均在应用／测试层绕开，不应据此要求修改 Shell 或 Makepad。
