# 不同 IDE 的独立 Agent 交付约定

2026-10-12 23:30前后新增；北京时间13日18:00冻结、21:00内部交付、24:00比赛硬截止。没有额度15%停止线。接手先读实际时钟，不能重新按22小时计算。

## 工作方式

不用聊天工具互相通信，不共享正在编辑的源码。必须共享同一份只读基线和接口契约，通过交付文件集成。先运行集成负责人阶段A（NF-00/01），产生 baseline_id、代码快照、runtime manifest、接口v1、角色目录与运行资源安排；然后U/S/H可以互不聊天地开发；最后负责人阶段B合流。阶段A准备期间各线可读源码与原型，但不自行定义互相矛盾的公共接口。

同一目录开三个IDE不构成隔离。建议每个角色拿快照副本到 D:/Life/AgenticApp/.parallel/night-20261013/<U|S|H>/，具体路径由负责人建立并记录。纯Git worktree默认不包含主工作区未提交/未跟踪文件；不得从HEAD裸建后误以为基线相同。负责人需将本轮必要工作区文件（包括实际未提交修改）准确纳入快照并给文件哈希，不复制个人数据、Provider、凭据或整棵build缓存。保留只读base副本以产生准确增量。可读共享运行时，私有输出/数据根不可共用。

跨电脑IDE：接收相同快照与交付协议，记录路径重映射及本机运行时；没有对应Windows宿主时只报静态/契约测试，不报Windows端到端。最终目标机器仍须最新整套运行时验收。

## 约定的优先级

共同目标是原型体验和两条真实入口；P0正确性/可用性/两条链路优先，P1详情整理其次，P2图片动画云端赛后。旧工作台保持业务和数据兼容。独立账本只做最小来源App。
应用业务仍用Splash；Shell只可做通用工具发现/身份/授权/路由/取消/错误/激活修复，不能装入DailyFlow业务。保留现有Cargo.lock与Makepad Windows d3d11修复。
新验收要求当次最新Shell、Hub、Makepad、OctoScript、桥接、内核及相关依赖；记录真实二进制哈希、本地补丁及官方发布门槛。历史报告不是新测试。运行时变更由负责人和H安排，不得三方各自更新或编译共享树。
少用computer-use；确需人的界面操作/授权时给出具体窗口和入口。不得自动批准、复制授权文件、打印凭据、把无人回应当作同意。

## 资源安排与最少文件交接

完全没有运行资源协调不可行：同机16GB只允许一个Rust构建和一场共享宿主/Provider验收。阶段A在dispatch.json明确runtime/host/build owner、排队时段和私有数据根，三线不抢占、不杀其他线进程。没有授予运行时段就继续静态/离线/私有数据测试，真实检查留待集成；不能因此伪报通过。H优先做平台探针，U/S不启动独立冷构建。

接口修改不能直接写共享契约。输出contract-change.md说明需要的改动、兼容旧v1办法、调用方影响；尽量在自己适配层兼容v1。确实不兼容时必须说明，不能赌最终自动合上。
H在完成两条探针后交一个probe-report.json（available/unavailable/unknown与真实证据），无需等待整条H实现完成。可由用户转交给S/I，也可经一次只读文件交接；这不是实时协作。如果坚持只最后交接，S只能做到传输适配待联调，NF-10/11/16不得先报passed，最终工期风险相应增加。

## 每线必须交付

在自己副本delivery/<role>/提供：
1. HANDOFF.md：目标、实际完成、未完成、下一条准确命令、对主工作区的接线说明。
2. manifest.json：role、baseline_id、contract_version、运行时版本/路径/哈希、每个改动文件的原哈希和新哈希、新增/删除清单、交付文件摘要。
3. changes.patch和新增文件；共享接线单独integration.patch。若工具无法生成可靠patch，可交逐文件base/new与替换说明，让I三方合并，不能只给包含旧文件的整个目录。
4. tests.json及报告/截图：测试命令、exit code、输入、性质（静态/注入/真实模型/真实宿主/真实GUI）、候选哈希。失败也保留。
5. TASK_RESULTS.json：所负责NF卡的局部结果与证据、未满足的前置、待联调项。只是交付报告，不是第二调度账本；各Agent不修改主execution-state.json。
6. contract-change.md（无改动写none）与活动进程清单：PID/用途/数据根/日志/是否已停。默认停止自己启动且确认属于自己的测试进程，不关闭用户或其他Agent窗口。
7. 无秘密/私人数据；模拟社媒与合成账目明确标记。新账本与旧账本不得重复统计相同业务数据。

完成局部范围就交付，不轮询等待其他Agent，不擅自扩张角色。接口未知可做明确标记的测试替身来开发，但替身/导入/旧黑板/应用内Agent成功均不能冒充新真实跨App或系统Assistant链路。
不commit/push/tag/publish/发送比赛材料；具体外发另行审核。根agent.md和主账本的汇总更新由I完成，角色在私有交接记录自己的进度。

## 最终集成

I先核对baseline和前哈希，再合并新增来源/入口模块、共享接线和UI；不能应用另一副本整个bundle覆盖当前产物。任何当前文件已变化都做三方合并。重建唯一候选、核对运行时，NF-12/15/16/17/18/19以最终集成候选实测；角色的局部成功不能自动标这些卡通过。即使I亲自执行后置测试，仍保留原角色卡ID和局部证据。

最终验收：系统Assistant新问题→新请求→真实来源读取→确定性同步→结构化整理→保存经历→冷/热启动定位；同时核对更正/删除/去重/撤权/取消、旧工作台、原型视觉。只有点击链接才能打开或只能文件导入，写清降级和未完成P0。
