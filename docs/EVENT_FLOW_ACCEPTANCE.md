## 真实黄金场景

无 Flow 名输入团子洗护 120 → 独立事实和费用；用品 35 → 同事件费用；10月11日15点后续计划 → 账目仍155；120更正110 → 同源 ID、合计145；查询145不写入；“一百多”不保存，追问后130才保存，总计275。图有事实、附属费用和计划的独立源引用，费用归属/明确后续安排均是持久关系。

另两次真实模型测试：两笔洗护费的含糊更正；不确定归属两次洗护中的哪次的用品。均追问，数据库修订和内容不变。所有模型输入为人工构造的测试语句；原 Provider 配置哈希由 harness 前后核对，未复制或打印密钥。

## 交互改进和真实缺陷修复

- 六个同级导航缩为日历/账本，数据管理为次级入口，统一输入不再要求切到独立聊天页。
- 日历视图切换保留月份、日期、事件范围；窄屏上下排列，宽屏月历与当天详情并排。
- 从图点击先进入读取态，再点击修改；保存仍是原费用 ID，返回保留上下文与图滚动位置。
- 图费用节点直接连到具体事项，明确安排标明来源事项编号，不以时间相邻推断关系。
- 开发失败证据保留：动态字符串字段不能直接当作静态字段访问；scope 是 Splash 保留字；错误日期字符串比较导致倒序；小日格长金额需要紧凑展示。相应代码已修复。ui1–ui6、real1–real2 等失败探针不计为通过。
- real-final 复跑曾发现模型漏填后续计划源 ID：业务虽保存了计划，但没有关系，测试失败。已增加限定在唯一既有事项内的明确后续安排引用保护；未把该次当作通过。

## 边界

本轮只在已有 Windows 桌面和 card-host 验证。跨 App/Shell Agent 传输、其他平台、后台唤醒、连续七天试用、签名和发布没有宣称完成。自动收据上限128、草稿不跨重启、双槽非断电事务、恢复旧备份回退收据仍是已知限制。商店发布身份/支持/隐私地址仍需真实资料；本次未发布也未伪造身份。
