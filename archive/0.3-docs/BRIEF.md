# DailyFlow 当前产品需求摘要

更新：2026-10-03（Asia/Shanghai）。状态：P0 体验与协议定稿已完成（文档），P1 及后续未授权。主文档：[修改计划与新Agent交接](docs/PET_CARE_FLOW_REPLAN.md)；P0 落地：[体验与协议定稿](docs/P0_EXPERIENCE_PROTOCOL.md)。旧多模块需求已退出当前范围。

## 用户已确认

- 暂时一个 App；内部严格分开记账与日历模块，先验证交互和协议。
- 只保留记账、普通/账本双视图日历及事件 Flow；宠物护理只是贯穿其中的验证事件，不是独立App。
- 交互需整体重做；用户通过自然语言表达，Agent自动组织Flow，信息明确自动记，含糊再问，不要求手工建组和连线。
- 日历能够在普通日历与账本日历间切换，同一月份和选中日期保持；账目与事件通过协议关联、更正一致。
- 其余产品需求删除、不占位；历史个人数据和备份保留。
- 业务标签由相应模块定义，用户可以自定义；公共Flow协议不拥有全局业务标签词表。

## 本次方案

主入口缩为日历和账本，统一输入就地记录；事件工作区显示事实、费用关联和用户明确提出的后续计划。记账模块拥有源账，日历消费版本化协议投影，Flow保存引用与关系。Agent需要验证自动归属、补充、更正和查询，不仅是把账目放到同一个分组。

先定可点击交互和模块契约，再收敛旧功能与设计数据迁移，之后可由三个Agent分别实现记账/协议、双视图日历、事件图/Agent；主Agent负责合并和真实验收。阶段、协议草案、删减清单和验收样例见主文档；P0 三视图原型、黄金场景、模块契约、图关系与状态迁移表见 [P0 体验与协议定稿](docs/P0_EXPERIENCE_PROTOCOL.md)。

## 当前实现与约束

当前源码仍为0.3.0，已有应用内真实模型自动记账、追问、Flow分组、持久化与基础时间线验证；本轮新交互、事件图及内部模块协议尚未实施。

仅使用OctoScript/Splash与现有获授权接口；不继续改Shell/Rust/Hub/Makepad，不新增原生业务后台。保留所有未提交成果、真实账本、锁文件与Windows修复。测试使用隔离数据，不提交、推送或发布。P0 已完成体验/协议定稿文档，代码未改、未删、未迁移数据、未启动子 Agent；P1/P2/P3/P4 仍待用户授权。
